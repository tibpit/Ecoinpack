# RedPen Profile

Brutally honest AI audit & rewrite of LinkedIn profiles, for the US market.

- **Free tier**: upload LinkedIn's "Save to PDF" export (or paste text) → 0–100 score + rewritten headline.
- **Paid tier ($19, one-time)**: full rewrite — About, every experience as copy-paste bullets, quick-wins checklist — delivered by email (Resend) and displayed on `/success`.

**Legal constraint baked in**: no scraping, no LinkedIn login. Input is user-uploaded only. Footer states "Not affiliated with LinkedIn Corporation".

## Stack

| Concern | Choice |
|---|---|
| Framework | Next.js 15 (App Router) + TypeScript + Tailwind CSS v4 |
| AI analysis | Anthropic API, `claude-sonnet-4-6`, structured outputs validated with zod (`lib/schema.ts`) |
| Payment | Stripe Checkout, one-time $19 |
| Email | Resend |
| Storage | Vercel Blob only — **no database in V1**. The paid result is regenerated by the Stripe webhook from the uploaded file (blob reference in the session metadata, 24h TTL). |
| PDF parsing | pdf-parse |

## Architecture / flow

```
/audit ── POST /api/analyze ──► rate limit (IP, 3/day)
                                ► PDF → text (pdf-parse) or pasted text
                                ► profile text → Vercel Blob  redpen/profiles/<uuid>.txt
                                ► Claude (claude-sonnet-4-6, JSON strict via zod)
                                ◄ FREE result: score + headline rewrite (rest stays server-side)

CTA ──── POST /api/checkout ──► Stripe Checkout session ($19, metadata = blobId + blobUrl)

Stripe ─ POST /api/stripe-webhook
                                ► verify signature (raw body)
                                ► re-run FULL analysis from the profile blob
                                ► store result   redpen/results/<session_id>.json (24h)
                                ► send Resend email (copy-paste blocks + how-to guide)
                                ► delete the profile blob

/success?session_id=cs_... ──► polls GET /api/session-result
                                ► verifies payment with Stripe, returns the stored result
                                ► before/after diff + Copy buttons per section
```

Vercel Blob has no native TTL: the 24-hour window is enforced on read (`lib/blob.ts`), the profile blob is deleted by the webhook, and the result blob expires the same way. Blob paths use UUIDs / Stripe session ids, so URLs are unguessable.

## Local development

```bash
cd redpen-profile
npm install
cp .env.example .env.local   # fill in every value (see comments inside)
npm run dev
```

To receive Stripe webhooks locally:

```bash
stripe login
stripe listen --forward-to localhost:3000/api/stripe-webhook
# copy the printed whsec_... into STRIPE_WEBHOOK_SECRET in .env.local
```

Test a payment with card `4242 4242 4242 4242`, any future date, any CVC.

## Deploying on Vercel

1. **Import the repo** on vercel.com → *Add New Project*. If this app lives in a subdirectory of the repo, set **Root Directory** to `redpen-profile`.
2. **Create a Blob store**: project → *Storage* → *Create* → *Blob*, and connect it. This injects `BLOB_READ_WRITE_TOKEN` automatically.
3. **Environment variables** (project → *Settings* → *Environment Variables*): set everything from `.env.example` — `ANTHROPIC_API_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` (step 5), `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `NEXT_PUBLIC_APP_URL` (your production URL, e.g. `https://redpenprofile.com`).
4. **Deploy** once so the production URL exists.
5. **Stripe webhook**: Stripe dashboard → *Developers* → *Webhooks* → *Add endpoint*:
   - Endpoint URL: `https://<your-domain>/api/stripe-webhook`
   - Events: `checkout.session.completed` (only this one is needed)
   - Copy the *Signing secret* (`whsec_...`) into `STRIPE_WEBHOOK_SECRET` on Vercel, then redeploy.
6. **Resend**: verify your sending domain in Resend, then use an address on it in `RESEND_FROM_EMAIL`.
7. Function durations: `/api/analyze` declares `maxDuration = 120` and the webhook `300`. On the Hobby plan functions cap lower — if analyses time out, upgrade the plan or lower `max_tokens`.

## V1 limitations (intentional)

- **Rate limiting** (`lib/rate-limit.ts`) is in-memory: on serverless it applies per warm instance, not globally. Acceptable as an abuse brake at launch; swap for Upstash Redis/Vercel KV for a hard guarantee.
- **Blob access** is `public` with unguessable UUID URLs (Vercel Blob has no private mode). TTL 24h + deletion after delivery keeps exposure minimal.
- The free analysis already runs the full model call but only returns score + headline to the client; the paid content never reaches the browser before payment.
